# Discord OAuth 연결 테스트

기존 `/연결 코드` → 앱 승인 경로를 유지합니다. 새 OAuth 경로는 테스트 등록 PC에서만 사용할 수 있습니다.

## 최초 준비
1. 변경된 서버를 기존 Git 배포 절차로 배포합니다.
2. Discord Developer Portal에서 기존 봇 애플리케이션의 **OAuth2 → Redirects**에 다음 주소를 추가하고 저장합니다.
   `https://erinn-desk-remote.lulufell.workers.dev/oauth/callback`
3. 서버 폴더에서 `python scripts/setup-oauth.py`를 실행합니다. 테스트할 디스코드 사용자 ID와 **OAuth2 Client Secret**을 입력합니다. Bot Token과 다릅니다. Secret은 화면/파일/앱에 저장하지 않고 Wrangler의 표준입력으로 Workers Secret에 등록합니다. Cloudflare 로그인 또는 기존 배포 권한이 필요합니다.
4. 테스트 EXE를 실행하고 디스코드 연결 페이지에서 **디스코드로 연결 · 테스트**를 누릅니다. 서버 연결을 켜고 기본 브라우저에서 Discord 인증을 엽니다. 승인 후 앱이 자동으로 연결 결과를 표시합니다.

실제 계정 승인, Client Secret 설정, 서버 배포는 로컬 자동 테스트에 포함되지 않습니다.

## 테스트판과 운영 관리
- 테스트판은 별도 Windows 설정 폴더 `ErinnDesk-OAuthTest`와 별도 실행 잠금을 사용합니다. 기존 앱의 설정/PC 인증정보를 가져오지 않습니다.
- 테스트 EXE는 별도 소스 복사본의 빌드 시 상수로 로컬 버전/EXE SHA 검증을 생략합니다. 일반 빌드의 기본값은 False이며 사용자 설정이나 환경변수로 활성화할 수 없습니다.
- `/register-test`가 발급한 서버 PC 레코드만 테스트 대상입니다. 기존 PC는 버전 헤더를 바꿔도 테스트 예외가 되지 않습니다.
- 테스트 PC는 서버의 `OAUTH_TEST_USERS`에 지정된 Discord 계정만 연결할 수 있습니다. **버전/배포 파일 등록은 생략**하지만 정책 유효기간·기능 점검·허용 목록·블랙리스트는 적용합니다. 서버의 `제한 범위=all`에 의한 로컬 기능 차단도 테스트판에서는 적용되지 않으므로 운영 배포용으로 제공하지 않습니다.
- 테스트 목록을 비우거나 Secret을 삭제하면 새 테스트 등록/연결 및 기존 테스트 계정의 조회를 차단합니다. 연결 해제는 계속 가능합니다.
- 브라우저 OAuth 인증은 계정 확인 목적의 `identify` 권한만 요청합니다. 인증 코드는 서버에서 교환하며 토큰은 DB/앱에 저장하지 않습니다. 계정 식별 후 토큰 폐기를 요청합니다.
- state는 5분 일회용, 앱 확정 토큰은 1분 일회용이며 인증을 시작한 PC WebSocket 세션에 묶습니다. 재접속하면 다시 인증합니다.
- 다른 PC/계정과의 기존 연결은 덮어쓰지 않습니다. 기존 앱 또는 디스코드 `/연결해제`로 해제 후 테스트합니다. 테스트 후 일반 앱으로 돌아갈 때도 테스트 연결을 먼저 해제합니다.
- 브라우저 인증 성공 페이지는 인증 결과만 안내합니다. 실제 연결 완료는 앱의 연결 계정 표시를 확인합니다.
- 이 단계에서는 일반 PC의 OAuth 시작을 차단합니다. 테스트 승인 후 이 제한과 테스트 전용 UI를 정식 연결 흐름으로 교체합니다. 기존 방식은 현재 제거하지 않았습니다.

## 빌드 재현
`python scripts/build-oauth-test.py --source <앱 소스 루트> --output <배포 출력 폴더> --stage <별도 oauth-test-source 폴더>`
PyInstaller와 기존 앱 빌드 의존성이 필요합니다. 앱 소스의 정식 버전/상수는 변경하지 않습니다.

## 인증 오류 확인
서버 변경 후 오류 문구에 단계와 HTTP 상태가 표시됩니다. token/invalid_client는 Application ID와 OAuth2 Client Secret을 확인하고, token/invalid_grant는 이전 브라우저 탭을 새로고침하지 말고 앱에서 새 인증을 시작하세요. identity는 계정 조회 단계, timeout은 해당 단계 응답 시간 초과입니다. 외부 응답 전문/토큰/Secret은 사용자에게 표시하지 않습니다. 서버 변경만 배포하면 되며 테스트 EXE 재빌드는 필요하지 않습니다.
