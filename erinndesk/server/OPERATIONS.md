# Erinn Desk 운영 관리

이 기능은 서버 코드와 앱 소스에 구현되어 있으며, 최초 운영 설정 게시 전에는 기존 서버 동작을 유지합니다.
1.4.8 EXE에는 운영 기능이 포함되지 않습니다. 운영 기능이 들어간 앱은 다음 1.4.9 빌드부터 적용합니다.

## 최초 준비

PowerShell에서 서버 폴더로 이동합니다.

```powershell
cd D:\Project\mabinogi-mobile-info\erinndesk\server
python -m pip install -r requirements-admin.txt
```

현재 개발 PC의 관리자 초기화는 완료했습니다. 다른 PC에서 처음 준비한다면 `python operations.py init`을 실행합니다.
기존 관리자 PC를 교체할 때는 새 키를 생성하지 말고 아래 암호화 백업을 복원합니다.

- 비밀키·관리자 토큰: `%LOCALAPPDATA%\ErinnDeskAdmin\credentials.dat`. 현재 Windows 사용자로 DPAPI 암호화됩니다.
- 공개 키: `operations-public.json`, `wrangler.jsonc`의 `OPS_PUBLIC_KEY`. 공개해도 되는 정보입니다.
- 앱: 공개 설정을 `site/operations-trust.json`으로 포함해 빌드합니다. 비밀키는 앱에 포함하지 않습니다.
- 관리자 도구 의존성은 Python/cryptography입니다. 앱 사용자는 설치할 필요가 없습니다.

### 서버 인증정보 등록과 배포

```powershell
python operations.py provision
```

기존 Wrangler 로그인 또는 로컬 Cloudflare 인증이 필요합니다. 이 명령은 운영 Worker에 `OPS_ADMIN_TOKEN` Secret을 등록합니다.
토큰을 화면에 출력하거나 Git에 저장하지 않습니다. 이 Secret은 기존 Cloudflare/Discord GitHub Secrets와 별개입니다.
그다음 변경한 서버 코드를 기존 main push 자동 배포로 반영합니다. `OPS_PUBLIC_KEY`도 함께 배포됩니다.
최초 준비가 끝난 뒤 운영 설정 변경에는 push나 서버 재배포가 필요 없습니다.

### 키 백업

```powershell
python operations.py backup
```

백업 파일 경로와 12자 이상의 암호를 입력합니다. 비밀키와 관리자 토큰이 암호화된 파일로 저장됩니다.
파일과 암호는 분리 보관하세요. 현재 PC의 DPAPI 파일만 복사해서는 다른 Windows 계정에서 복원할 수 없습니다.
새 PC에서는 `python operations.py restore`로 암호화 백업을 복원하고 `python operations.py init`으로 공개 설정을 내보냅니다.
기존 키를 잃으면 새 공개 키가 들어간 앱 재배포가 필요하므로 운영 시작 전에 백업하세요.

## 평소 관리

```powershell
.\관리자도구.ps1 ops
```

또는 `python operations.py`를 실행합니다. 모든 변경은 적용 전 내용을 보여주고 `적용`을 입력해야 게시합니다.
서버 설정에는 번호가 붙으며, 다른 관리 작업이 먼저 반영됐다면 덮어쓰지 않고 다시 불러오도록 안내합니다.

1. **상태 확인**: 현재 정책·허용 목록·만료까지 남은 일수 확인.
2. **새 버전 게시**: 최종 EXE 경로·버전·직접 다운로드 주소 입력. 게시된 파일을 내려받아 크기와 SHA256을 비교한 뒤 서명합니다.
3. **지원/차단 버전**: 최소 지원 버전, 특정 차단 버전, 제한 범위와 안내 문구 설정.
4. **기능 점검**: discord(전체), link(신규 연결), items(아이템), capture(스크린샷)별 사용/점검과 사유 설정.
5. **허용 사용자**: all(전체), allowlist(허용 목록), maintenance(점검) 모드 및 Discord 사용자 ID·메모 관리.
6. **이력 복원**: 최근 100개 이전 설정에서 선택. 새 정책 번호와 서명으로 복원하며 이미 게시한 버전의 파일 정보는 유지합니다.
7. **정책 갱신**: 기능·버전 설정을 유지하고 유효기간을 갱신합니다.

**첫 설정은 2번 새 버전 게시부터 진행합니다.** 공식 파일 정보가 없으면 정책을 게시할 수 없습니다. 최초 게시 시 접근 모드와 구버전 유예 종료일을 선택합니다. 기본값은 허용 목록 모드/등록 사용자 없음이며, 기존 전체 이용자를 유지하려면 all을 선택합니다. 허용 목록 모드라면 5번에서 본인과 테스터를 추가합니다.
다운로드 파일 업로드 자체는 현재 도구에서 처리하지 않습니다. 기존 배포 페이지/다운로드 저장소에 먼저 업로드하세요.
동일 버전의 EXE를 바꾸지 마세요. 서버도 이미 게시한 버전의 해시·파일 크기 교체를 거절합니다.

## 버전 운영 예

- 최신 1.4.10 / 최소 1.4.9: 1.4.9는 업데이트 권장, 1.4.10은 정상 사용.
- 최소 1.4.10 / 범위 discord: 구버전 디스코드 기능 제한, 로컬 기능 계속 이용.
- 범위 all: 새 CLI 요청 전에 제한. 실행 중인 요청을 강제 종료하지 않으며 행동 중단·앱 종료는 가능합니다.
- 특정 버전만 문제라면 차단 목록에 추가합니다. 버전은 숫자별로 비교하므로 1.4.10은 1.4.9보다 새 버전입니다.
- 클라이언트 버전은 서버에 전달되는 값이며 변조 앱의 위조 불가능한 증명이 아닙니다. 권한은 서버에서 별도로 검사합니다.
- 운영 기능이 없는 기존 앱의 로컬 기능에는 제한을 소급 적용할 수 없습니다. 버전 헤더 없는 앱은 설정한 구버전 유예 기한까지 임시 허용할 수 있으며, 미설정/기한 종료 시 디스코드 기능이 제한됩니다.

## 점검·접근 제한

- 기능 점검, 사용자 제외, 버전 제한은 연결 승인·명령·응답 전달에서 확인합니다.
- 정책 변경으로 금지된 처리 대기 요청은 취소 안내하고 민감한 결과를 전송하지 않습니다.
- 신규 연결만 점검하면 기존 사용자의 조회는 계속 이용할 수 있습니다.
- 점검/허용 목록 제외 중에도 연결 해제는 가능합니다. 기존 PC 인증정보가 있으면 앱이 연결 해제/등록 삭제를 위한 통신은 유지할 수 있지만 조회·화면 전송은 별도로 차단합니다. 점검만으로 등록 정보를 삭제하지 않습니다.
- 허용 목록은 관리자 API에만 있으며 공개 `/policy` 응답과 앱에는 포함되지 않습니다.
- 앱은 설정 변경 알림 또는 주기적 확인으로 안내를 갱신합니다. 서버 제한은 앱 화면 갱신과 무관하게 적용됩니다.

## 검증·장애·유효기간

- 앱은 실행 EXE를 한 번 해시 계산하고 자기 버전의 서명된 공식 파일 정보와 비교합니다.
- 불일치/미등록 파일이면 재다운로드를 안내하고 디스코드 기능을 제한합니다. 개발 소스 실행은 별도 개발 상태로 취급합니다.
- 서명된 정책은 매분 확인합니다. 네트워크 오류에는 마지막 확인 후 최대 10분까지 캐시를 사용하며 재시작해도 유예 시간이 초기화되지 않습니다.
- 유예/정책 만료 후 디스코드 기능을 제한합니다. 서버 연결 실패만으로 로컬 기능을 새로 제한하지 않습니다.
- 이미 확인된 구버전 로컬 제한은 오프라인/만료 뒤에도 유지됩니다. 중단 요청과 앱 종료는 계속 가능합니다.
- 정책 게시/갱신 시 유효기간은 30일입니다. **운영 도구 7번으로 만료 전에 갱신해야 합니다.** 서버는 만료 정책으로 디스코드 이용을 허용하지 않습니다.
- 서명과 SHA 검사는 정상 앱의 손상/변경 탐지 기능이며, 변조 앱의 자체 검사 우회까지 막는 원격 인증 기능은 아닙니다.
- HTTPS로 전달하며 정책 번호 역행·동일 번호 내용 교체·서명 변조를 거절합니다. 설정 복원도 반드시 새 번호로 서명합니다.
- 관리자 인증정보는 요청 헤더로만 전달합니다. 관리자 요청의 리다이렉트를 따라가지 않습니다.

## 운영 시작 순서

1. 관리자 키 암호화 백업.
2. 관리자 Secret 등록, 서버 코드 push 및 자동 배포 확인.
3. 운영 기능 포함 1.4.9 EXE 빌드·다운로드 파일 업로드.
4. 관리자 도구 2번에서 1.4.9 파일 검증 후 최초 게시. 최소 버전과 허용 목록을 함께 확인.
5. 정상 파일 검증·업데이트 안내·테스터 연결 확인.
6. 필요할 때만 최소 버전 상승/점검/허용 목록 전환.

최초 게시 전까지 정책이 없어 기존 서버 동작을 유지하는 것은 배포 순서에 따른 의도적인 호환 처리입니다.
초기 게시 후에는 정책을 삭제해 이전 동작으로 돌아가지 않고, 새 설정으로 수정/복원합니다.


## 구버전 업데이트 유예

- 최초 버전 게시(2번) 또는 지원/차단 버전 설정(3번)에서 종료일을 한국시간 `YYYY-MM-DD HH:MM`으로 입력합니다.
- Enter는 현재 기한 유지, `해제`는 즉시 유예 종료입니다. 기본값은 유예 없음이며 실제 기한은 관리자가 선택합니다.
- 현재부터 30일 이내로 입력합니다. 유예 종료는 서명된 정책의 만료를 넘길 수 없습니다.
- 정책 갱신/새 버전 게시만으로 유예 종료가 자동 연장되지는 않습니다. 필요하면 종료일을 명시적으로 변경합니다.
- 유예는 **버전 정보를 보내지 않는 기존 앱**에만 적용합니다. 버전 값을 보내는 앱의 최소 버전/특정 버전 차단이나 잘못된 버전 문자열은 예외가 아닙니다.
- 기능 점검, 허용 목록, 정책 만료는 유예 중에도 그대로 적용합니다. 기존 전체 사용자를 유지하려면 접근 모드는 all이어야 합니다.
- 기한이 지나면 다음 디스코드 요청/민감한 결과 전달부터 버전을 제한합니다. 기존 연결 기록은 삭제하지 않으며 연결 해제는 가능합니다.
- 제한 응답에 업데이트 안내와 길이가 허용되는 경우 최신 파일 다운로드 주소를 표시합니다. 구버전 앱 내부에 새 업데이트 팝업을 소급 추가하지는 못합니다.
- 이 예외는 구버전 호환을 위한 것으로, 버전 헤더를 생략하는 변조 앱을 구별하는 보안 인증 기능은 아닙니다. 유예는 필요한 기간만 설정하세요.
- 서버/관리 도구 변경이며, 기존 1.4.9 EXE는 그대로 사용할 수 있습니다. 서버 배포·최초 정책 게시 전에는 실제 사용자에게 적용되지 않습니다.


## 웹 화면으로 관리하기

기존 CLI 대신 `관리페이지.cmd` 또는 `관리자도구.ps1 web`으로 로컬 관리 페이지를 사용할 수 있습니다. 세부 내용은 [ADMIN-PAGE.md](ADMIN-PAGE.md)를 확인하세요. 정책 서명과 인증정보는 CLI와 같은 PC 저장소를 사용하고, 모든 운영 변경은 차이 확인 후 적용합니다.
